# 多语言、会话分流与 M11 输入输出

> 状态：阶段 1（会话、双语、安装器、USB 枚举）已落地；USB 批量读写与多显示器
> 镜像仍在进行中。本文只记录已经验证的行为，未完成部分明确标注。

## 1. live 免登录与安装后首次设置

- **live 介质**（根文件系统来自 `SYSTEM.IMG`，`novusfs_root_persistent()==0`）：
  `session_init()` 直接进入名为 `live` 的会话，`session_logged_in()` 为真，
  桌面应用立即启动，不显示用户名/密码窗口。
- **已安装系统**（根文件系统是可写的 NovusFS 分区）：保持首次创建账户 → 登录；
  账户记录仍是 `/users.db`（加盐哈希）。
- **安装模式**（`boot_mode=INSTALL`）：只启动 `setup`，不初始化会话、不打开桌面。
- 开始菜单页脚在 live 下显示"Live 会话 / Live session"，已安装系统显示用户名。

验证：串口出现 `[SESSION] live session: no account required`；安装后的磁盘启动
出现 `[SESSION] first boot; account setup required`。

## 2. 中英双语

### 2.1 文案与翻译

- 每个界面字符串以中文原文为键，英文翻译集中在
  `tools/langgen/strings*.toml`；`tools/langgen/langgen.py` 生成
  `graphics/nd_lang_dict.c`（C 二分查找表）与 `apps/src/lang_dict.rs`
  （Rust 同一张表）。
- 渲染层统一翻译：`nd_text()` / `nd_text_width()` / `nd_text_height()` 入口
  调用 `nd_lang_tr()`，所以壳层、窗口标题、内置应用与安装器的文字无需逐个改调用点；
  Rust 侧 `ui::width()` 用同一张表测量，保证英文排版与像素一致。
- 缺失翻译时回退中文，不显示 id 或空串。

### 2.2 切换与持久化

- `SYSINFO_REQ_LANG (0x030F)`：`{set,value}` → `{lang,version}`；
  内核 `nd_lang_set()` 递增版本。
- 安装器首屏、设置 → 个性化 → 语言都可切换；壳层在空闲 tick 比较语言版本并整屏重绘，
  Rust 应用在 `ui::poll()` 中比较版本后重绘。
- 已安装系统把语言写入 `/language.cfg`（`{magic,lang}`），启动时
  `lang_init()` 在绘制第一帧前读取；live 下只存内存。
- 安装器在"校验"阶段把安装语言写入新系统分区并重建 Merkle 树，首次启动即继承。

验证：安装时点击 English，串口 `[LANG] loaded: en`，安装后的系统首次设置窗口
与桌面磁贴全部为英文。

## 3. 安装器（七页）

语言 → 协议 → 磁盘 → 方案 → 确认 → 进度 → 完成/失败。

- 语言页：中文 / English 两个大按钮，切换立即生效。
- 协议页：GPLv2 分发与免责、整盘清除、备份与电源提示；必须勾选同意才能继续。
- 方案页：文件系统三选一；**NovusFS 可选并实际安装**，NTFS/ext4 标注"规划中 /
  Planned"且不可选（驱动里程碑尚未实现，选择会被内核以 `INSTALL_ERR_FS` 拒绝）。
- 其它页面与 M10 一致；键盘 `Enter/Esc/↑↓/Space` 全程可用。

## 4. USB 存储

`kernel/usb.c` 实现了一个 xHCI 控制器加一个批量传输（BOT）磁盘：

- **PCI 64 位 BAR**：`kernel/pci.c` 现在按 64 位 BAR 对读取基址与长度
  （`bar64[]` / `bar_size[]`），并提供 `pci_bar_assign()` 改写 BAR。
  固件常把 xHCI 的 BAR0 放在 4 GiB 以上，而内核的恒等映射只覆盖 4 GiB，
  因此驱动会把它搬到 32 位 PCI 空洞里，并**读回能力寄存器确认控制器
  真的在那里应答**（`[USB] BAR0 moved to 0x...`）。
- **xHCI**：命令环、事件环、ERST、端口复位与速度识别、Enable Slot、
  Address Device、GET_DESCRIPTOR、SET_CONFIGURATION、Configure Endpoint。
  输入控制上下文的 drop/add 标志与端点 DCI 编号必须与规范一致，否则
  控制器会直接返回 TRB Error。
- **BOT**：CBW/CSW、INQUIRY、READ CAPACITY、READ10/WRITE10。
  命令块与数据阶段必须使用**不同的缓冲**，否则包装器会覆盖待写数据。
- 所有等待都有上限；任何一步失败只打印一行日志，机器照常启动。

### 4.1 作为安装目标

- 可移除介质（U 盘、移动硬盘）是合法的安装目标；向导会标注"USB 可移除"。
- **正在启动的介质永远不是目标**：引导阶段从引导卷的设备路径解析出
  USB 端口并写入共享内存（`boot_usb_port` 与 `SHM_INSTALL_FLAG_BOOT_USB`），
  内核据此给该盘打上 `BLKDEV_FLAG_BOOT_ONLY`，向导显示"当前正在从这块盘启动"。
- 设备路径里的端口号与 xHCI 根端口可能相差 1，两种编号都接受；
  若无法唯一确定（多个 USB 卷），则所有 USB 盘都拒绝作为目标。

## 5. 多显示器与连接器

引导阶段 `nd_capture_boot()` 现在枚举固件提供的**每一个** GOP 输出：

1. `LocateHandleBuffer(AllHandles, GOP)` 拿到所有输出句柄（上限 4 个）；
2. 对每个输出读 `EFI_EDID_ACTIVE_PROTOCOL`：第一个详细时序就是显示器的首选
   分辨率，字节 20 的 bit 7 说明链路是数字（DP/eDP/HDMI）还是模拟（VGA）；
3. 若控制器提供与首选一致且可绘制的模式（32bpp、RGB/BGR、帧缓冲在 4 GiB 以内），
   就 `SetMode` 切过去；否则保留固件选定的模式；
4. 第一个输出作为主屏，其余输出**镜像**同一画面。

内核侧：

- `nd_outputs()` 返回"每个帧缓冲一个条目"的清单——固件常会列出指向同一块显存的
  第二个头衔，把它当成一块显示器是假话；
- `nd_mirror_rect(rect)` 在主屏绘制完成后，把该矩形复制到其余输出，两个帧缓冲
  字节序不同时逐像素交换红蓝，并按较小输出裁剪（1080p 桌面接到 4K 屏上时画面在
  左上角，不会跑出屏幕）；
- 设置 → 系统新增"显示输出"卡片：每行一个输出，含分辨率、主屏/镜像、数字/模拟，
   与 EDID 首选不一致时标注首选值；数据来自新的 `SYSINFO_REQ_DISPLAY (0x0318)`。

**连接器命名**：固件只给出"数字/模拟"，eDP/DP/HDMI/VGA 的精确区分属于原生显示
驱动里程碑，本文如实标注为"数字输出/模拟输出"。

### 5.1 顺带修掉的窗口重绘缺陷

显示列表原来在每条 SHAPE/TEXT 到达时各自触发重绘，客户端一帧要发 50 余条消息，
于是**半帧状态会闪现在屏幕上**（关掉遮挡窗口后，下面窗口的内容只剩一半）。
现在 SHAPE/TEXT/CLEAR 只入库，由帧尾的 INVALIDATE 一次性重绘——
半帧永远到不了屏幕，重绘次数也下降到每帧一次。

## 6. 验证命令

```bash
make && make iso
scripts/run-install-test.sh 256          # 标准安装（AHCI 目标）
EN=1 scripts/run-install-test.sh 256     # 英文安装
FLOW=desktop scripts/run-install-test.sh 64
EXTRA='-device qemu-xhci,id=xhci1,p2=4,p3=0 \
       -drive if=none,id=ustick,file=/tmp/usb.img,format=raw \
       -device usb-storage,drive=ustick,bus=xhci1.0' \
  FLOW=desktop scripts/run-install-test.sh 64   # USB 枚举日志
```

只带 U 盘、没有 SATA 盘的完整安装（脚本在 `/tmp/usb-install-test.sh` 一类的
一次性脚本里）：QEMU 只挂 `usb-storage`，菜单选 3 后用键盘走完七页，
串口应出现 `begin on usb00` 到 `install complete`；再用同一镜像启动该盘，
应出现 `[BOOT] live medium is on USB` 与 `is the boot medium`。
