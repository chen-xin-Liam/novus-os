# Novus OS 图形安装向导设计与实现（M10）

> 状态：已实现并通过 QEMU 端到端验证
> 代码：`apps/src/bin/setup.rs`、`apps/src/install.rs`、`kernel/install.c`
> 相关：`arch/x86_64/boot/stage3.c`、`kernel/shared_mem.h`、`kernel/trap.c`

## 1. 目标与边界

把原先 UEFI 控制台里的"按 3 直接写盘"改成进入系统图形环境后的分步向导：
可以看清目标磁盘、看清会清掉什么、写入过程有阶段与百分比、失败有原因。

边界：

- 只处理**本机可写整盘**（AHCI/NVMe/USB）。可移除介质（U 盘、移动硬盘）可以作为
  目标，但**正在启动的那块盘不行**；无法确定启动盘时，所有 USB 盘都拒绝作为目标。
- 不修改 NUC、GPT、FAT、NovusFS 的磁盘格式；只增加读写与校验接口。
- 不改变文本安装路径：`CONFIG_NOVUS_INSTALLER_TEXT=1` 时仍可在引导阶段直接安装，
  作为无帧缓冲设备的回退。

## 2. 三段式架构

```
UEFI 引导阶段 stage3.c
  ├─ esp_read_reserved("SYSTEM.IMG") → live_root_base/size
  ├─ esp_read_reserved("ESP.IMG")    → esp_img_base/size   （M10 新增）
  └─ 菜单 3 / INSTALL.YES → boot_mode = SHM_BOOT_MODE_INSTALL
                 │  ExitBootServices（此后读不到 ESP）
                 ▼
内核 install.c
  ├─ install_init(): 把两个物理地址映射为直接映射指针
  ├─ install_disk(): 候选盘与不可选原因
  ├─ install_begin(): 全部校验在第一次写入之前完成
  └─ install_step(): 128 KiB 一步的复制 / 建表 / 校验
                 │  SYS_SETUP(19)
                 ▼
用户态 setup.rs（Novus-WM 客户端）
  欢迎 → 磁盘 → 方案 → 确认 → 进度 → 完成/失败
```

为什么不在引导阶段画图：那里只有 `EFI_SIMPLE_TEXT_OUTPUT`，字体、主题、圆角、
中文输入以及 Novus-WM 都不存在；为什么不在内核里画：内核 tick 不能阻塞在 20 MiB
的复制上，且窗口协议已经提供了沙箱化的绘制路径。

## 3. 引导阶段

### 3.1 载荷暂存

`stage3_prepare()` 在 `ExitBootServices` 之前把两份镜像读进 reserved pages：

| 载荷 | 用途 | 共享内存字段 |
|------|------|--------------|
| `SYSTEM.IMG` | 系统分区镜像（NovusFS） | `live_root_base` / `live_root_size`（0x2B0 / 0x2B8） |
| `ESP.IMG` | 引导分区模板（BOOTX64.EFI + SYSTEM.IMG） | `esp_img_base` / `esp_img_size`（0x2F0 / 0x2F8） |
| 状态位 | 两份都在 | `install_flags`（0x300），bit0 = `SHM_INSTALL_FLAG_PAYLOADS` |

`shared_mem_t` 是冻结布局：新字段只允许追加在 0x2F0 起的 reserved 尾部，总大小仍为
8 KiB，并在头文件里断言偏移（`esp_img_base == 0x2F0`、`install_flags == 0x300`、
`reserved == 0x304`）。

### 3.2 入口

| 入口 | 行为 |
|------|------|
| 菜单 `3 Install Novus (graphical wizard)` | 设置 `boot_mode=INSTALL`，继续进入内核 |
| ESP 根目录 `INSTALL.YES` | 同上，不显示菜单（无人值守） |
| 普通启动 | `boot_mode=LIVE`，进入登录/桌面 |
| `CONFIG_NOVUS_INSTALLER_TEXT=1` | 上述两个入口改走 `install_run()` 文本安装 |

内核 `kmain()` 在 `install_init()` 之后检查 `boot_mode`：安装模式直接
`apps_launch_name("setup")`，**不启动登录窗**；普通模式启动 `session`。

## 4. 内核安装服务

### 4.1 候选盘判定

`install_disk()` 对每个块设备给出 `eligible` 与 `reason`，向导原样展示：

| 原因码 | 条件 |
|--------|------|
| `INSTALL_E_PARTITION` | `BLKDEV_FLAG_PARTITION`，是分区视图不是整盘 |
| `INSTALL_E_READONLY` | 只读介质 |
| `INSTALL_E_BOOT_MEDIUM` | `BLKDEV_FLAG_BOOT_ONLY`：系统正从这块盘启动 |
| `INSTALL_E_SMALL` | 小于 64 MiB |
| `INSTALL_E_FOREIGN` | `gpt_read()` 成功且分区数 > 0：已有分区表，可能属于其他系统 |
| `INSTALL_OK` | 以上都不成立（裸盘，或 Novus 自身两分区布局） |

**安全取舍**：裸盘直接可选；已有分区表时，只有**恰好是 Novus 自己的布局**
（2 个分区，且分别能被 `gpt_find_esp` / `gpt_find_novusfs` 找到）才放行，
这样失败或中断后的重试不必回到主机侧清表。任何其他布局都判为外来系统并拒绝，
避免把正在运行的 Windows/Linux 盘写成安装目标。

### 4.2 写入几何

与 `mkdisk` 一致：

```
LBA 2048                 ESP        ceil(esp_bytes / 512) 按 1 MiB 对齐
ESP 之后                 系统分区    ceil(sys_bytes / 512) 按 1 MiB 对齐
末尾保留 64 扇区          备份 GPT
```

`install_begin()` 先检查载荷存在、长度为 512 整数倍、两份镜像放得下目标盘；
任何一项失败都不会写盘。

### 4.3 分步状态机

`install_step()` 每次只做有界工作，然后把 `install_progress_t` 交给调用者：

| 阶段 | 工作 | 说明 |
|------|------|------|
| `TABLE` | `gpt_write()` 写保护性 MBR + 主/备 GPT | 一步完成，毫秒级；成功后 `g_table_written=1` |
| `ESP` | 每次最多 256 扇区（128 KiB）写入 | 直到 `esp_bytes` |
| `SYSTEM` | 同上 | 直到 `sys_bytes` |
| `VERIFY` | `blkdev_partition_init` → `novusfs_mount` → `novusfs_merkle_verify` → `unmount` → `blkdev_release` | 根哈希缺失时补建；不匹配即失败 |
| `DONE` | `permille=1000` | 客户端切到完成页 |
| `FAIL` | `err` 给出原因 | 客户端切到失败页 |

进度：建表 30%，复制 30%→96%（按已写字节），校验 97%，完成 100%。

阶段切换才写 COM1（`[INST] ...`），每一步不打印，避免串口拖慢安装。

### 4.4 授权与生命周期

- `apps_launch()` 启动 `setup` 成功后调用 `install_authorize(pid)`，`SYS_SETUP`
  只接受该 pid；其他应用（包括设置里的"打开安装程序"若启动失败）无法调用。
- 单实例：`apps_launch` 按名字拒绝第二个 `setup`。
- `install_abort()` 只在分区表写入前有效；写入开始后返回 -1，向导把按钮变成说明文字。
- 失败后 `install_reset()` 清状态，`blkdev_release()` 归还分区视图槽位，允许重试。

## 5. SYS_SETUP 系统调用（编号 19）

只追加，不改变 1–18 与 60 的语义。参数沿用 `syscall` 门：`rdi=op`、
`rsi=arg`、`rdx=user_ptr`。

| op | 名称 | 参数 | 返回 |
|----|------|------|------|
| 0 | `COUNT` | — | 块设备数量 |
| 1 | `GET` | index → `install_disk_t` | 0 / -1 |
| 2 | `BEGIN` | index | 0 / -1 |
| 3 | `STEP` | → `install_progress_t` | 当前阶段（0–6）/ -1 |
| 4 | `ABORT` | — | 0 / -1 |
| 5 | `STAT` | → `install_progress_t` | 0 / -1 |
| 6 | `RESET` | — | 0 / -1 |

```c
typedef struct {
  char   name[12];
  UINT64 sectors;
  UINT32 block_size;
  UINT8  flags;     /* BLKDEV_FLAG_* 低 8 位 */
  UINT8  eligible;
  UINT8  reason;    /* INSTALL_E_* */
  UINT8  pad;
} install_disk_t;      /* 32 字节 */

typedef struct {
  UINT8  phase;     /* INSTALL_PHASE_* */
  UINT8  err;       /* INSTALL_ERR_* */
  UINT16 permille;  /* 0–1000 */
  UINT32 done_kb;
  UINT32 total_kb;
} install_progress_t;  /* 12 字节 */
```

Rust 侧 `apps/src/install.rs` 用 `repr(C)` 镜像这两个结构，并以
`size_of` 断言锁定布局。

## 6. 向导页面与交互

窗口 900×600，位于 1280×800 屏幕中央；左侧 240 px 品牌与步骤导航，右侧 612 px 内容。

M11 起为七页：**语言 → 协议 → 磁盘 → 方案 → 确认 → 进度 → 完成/失败**。
语言页同时承担欢迎内容；协议页是新增的 EULA 页，必须勾选同意才能继续。

| 页 | 内容 | 主操作 |
|----|------|--------|
| 语言 | 中文 / English 两个大按钮，切换立即影响整机 UI | 下一步 |
| 协议 | GPLv2 分发与免责、整盘清除、备份与电源提示；勾选同意 | 同意并继续 |
| 磁盘 | 全部块设备 + 容量 + 可用/原因；选中盘下方红色"将清除整盘数据" | 下一步（无可用盘时是"刷新"） |
| 方案 | 文件系统三选一（NovusFS 可选；NTFS/ext4 标注"规划中"并置灰）、GPT 两分区布局、目标磁盘摘要 | 继续 |
| 确认 | 目标盘、分区重建说明、红色警告卡、勾选确认 | 开始安装（未勾选禁用） |
| 进度 | 四阶段清单、总进度条、已写/总量、取消策略 | 取消（仅建表前） |
| 完成 | 校验通过、重启后从新盘启动的提示 | 立即重启 / 关机 |
| 失败 | 错误码的可读原因、建议、目标盘可能不可启动 | 重试 / 返回 |

键盘：`Enter` 主操作、`Esc` 返回、`↑/↓` 选择磁盘、`Space` 勾选确认。
窗口关闭按钮不生效：安装模式下它是唯一界面，关掉会让系统停在无处可去的桌面。

## 7. 错误码

| err | 含义 | 用户文案 |
|-----|------|----------|
| 1 | 分区表写入失败 | 无法写入分区表 |
| 2 | 载荷写入失败 | 写入安装数据失败 |
| 3 | 新分区挂载失败 | 无法挂载新的系统分区 |
| 4 | 完整性校验失败 | 完整性校验失败 |
| 5 | 内存不足 | 内存不足 |
| 6 | 参数/状态错误 | 安装失败 |

失败一致性：GPT 写入成功即视为已提交，后续失败不回滚分区表；失败页必须提示
"目标磁盘可能已经不再是可以启动的系统盘"。

## 9. 已知限制

1. USB 目标由内核的 xHCI 驱动提供（一个控制器、一个批量传输设备）；
   不支持 USB 集线器、UAS、热插拔与 USB 3 流。
2. 已有非 Novus 分区表的磁盘一律拒绝；Novus 自身两分区布局允许覆盖重装。
3. 安装后的磁盘 ESP 中没有 `ESP.IMG`，因此在已安装系统里"安装到磁盘"会提示
   载荷未就绪；这是有意的：安装程序属于安装介质，不属于已安装系统。
4. 安装模式不启动登录与会话；live 介质免登录，首次启动安装后的系统时创建账户。
