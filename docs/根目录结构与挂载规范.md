# Novus OS 根目录结构与挂载规范

本规范描述系统盘、安装 ISO 与 ESP 上的统一根目录树，以及 `disk0`、`disk1`、
`media/*` 的真实挂载语义。唯一真源是
`fs/novusfs/rootfs_layout.h`；本文件是它的可读说明。

## 1. 目录树

```
/
├─.novusfs
│  ├─fsinfo              # 静态卷信息文本
│  ├─mounts.json         # 可读挂载表
│  └─trash
├─disk0                  # 挂载点
├─disk1                  # 挂载点
├─media
│  ├─cdrom0              # 挂载点
│  ├─usb0                # 挂载点
│  └─usb1                # 挂载点
├─Novus
│  ├─bin  boot  fonts
│  ├─kernel/{core,syscalls}
│  ├─logs/{boot,security,service}
│  ├─modules/{input,network,storage}
│  ├─services
│  ├─syslib/{libc,libgui,libio}
│  └─wincompat/{system32,syswow64}
├─Program Files
├─Program Files (Windows)
├─ProgramData
│  ├─NovusApps  SharedResources  WinApps
│  └─Security/{certificates,policy}
├─temp/{system,user/{uid_0001,uid_0002}}
└─Users
   ├─alice
   │  ├─.novus/{cache,config,desktop-shortcuts,keystore,shell_history,ssh}
   │  ├─.winprefix/{Program Files,ProgramData,users/alice,Windows/system32}
   │  ├─AppData/{Local,Roaming}
   │  └─Desktop Documents Downloads Music Pictures "Saved Games" Videos
   └─Public/{Desktop,Documents,Downloads,Pictures,SharedApps}
```

共 77 个目录、2 个元数据文件。`novusfs_format()` 在格式化时通过
`novusfs_seed_root()` 建树，因此主机生成的 `out/novus.img`、安装后的 GPT
系统分区、live 会话的 ramdisk 根完全一致。

## 2. 三套镜像的名称映射

| 镜像 | 格式 | 名称 | 备注 |
| --- | --- | --- | --- |
| `out/novus.img` | NovusFS | 原名，大小写敏感 | 可写；真实挂载只发生在这里 |
| `out/novus-live.iso` 主描述符 | ISO 9660 | 8.3 大写别名 | 标准兼容，`dir_find` 自检使用 |
| `out/novus-live.iso` Joliet SVD | Joliet (UCS-2BE) | 原名 | 挂载/解包时显示 `Program Files`、`.novusfs` 等 |
| `out/esp-tpl.img` / `out/esp.img` | FAT16/32 | 8.3 大写别名 | 固件只认 8.3；无 LFN |

FAT/ISO 主描述符的引导文件位置不变：`EFI/BOOT/BOOTX64.EFI`、
`SYSTEM.IMG`、`ESP.IMG`，El Torito 与 isohybrid 分区表不受影响。

别名是确定性的，例如：

| 原名 | 别名 |
| --- | --- |
| `.novusfs` | `NOVUSFS` |
| `Program Files` | `PROGFILE` |
| `Program Files (Windows)` | `PROGFWIN` |
| `SharedResources` | `SHAREDR` |
| `desktop-shortcuts` | `DESKTOPS` |
| `Saved Games` | `SAVEDGAM` |
| `mounts.json` | `MOUNTS.JSO` |

ISO 与 ESP 中的 `disk0`、`media/*` 只是静态目录镜像；插入介质后的内容只在
可写的 NovusFS 根上通过真实挂载出现。

## 3. `.novusfs` 元数据

`fsinfo` 是纯文本卷信息（`volume=`、`fstype=`、`block=`、`layout=`、`dirs=`）。
`mounts.json` 是固定键的扁平表，每行一个对象，无嵌套、无转义、总长 ≤ 4 KiB、
最多 8 条：

```json
{"path":"/disk0","dev":"disk0","fstype":"auto","options":"rw"}
```

- `path`：必须是 `rootfs_layout.h` 的 `NOVUS_LAYOUT_MOUNTS` 白名单路径。
- `dev`：`root` 或逻辑设备名 `diskN` / `usbN` / `cdromN`。
- `fstype`：`auto`、`novusfs`、`ext4`、`fat`、`iso9660`。
- `options`：`rw` 或 `ro`。

内核 `kernel/mountcfg.c` 启动时读取该文件并按块设备标志
（`REMOVABLE` / `READONLY`）把探测到的设备分类为逻辑名；`auto` 依次识别
ISO9660（LBA16 的 `CD001`）、FAT（BPB/签名）、NovusFS（`NOVS`）与 ext4。
运行时 `mount`/`umount` **不回写** 该文件：写受保护块会使下次启动的
Merkle 校验失败。

## 5. 挂载实现

`fs/vfs_mount.c` 维护固定 8 项挂载表，`vfs_resolve_path()` 逐组件遍历路径，
命中挂载前缀时切换到该卷的 `vfs_fs_t` 根 inode。文件描述符
（`kernel/sched.h`）记录后端指针，因此 `ls`、`cd`、`cat`、`tree` 可以跨挂载点。
只读后端（FAT / ISO9660）的写类 syscall 在到达后端前被拒绝；跨挂载点的
`rename` 被拒绝；挂载点本身不能被删除。

后端：

- NovusFS（可写）、ext4（已有实现）
- `fs/fat/`：FAT12/16/32，8.3 短名，跳过 LFN，只读
- `fs/iso9660/`：优先 Joliet SVD，否则主描述符，只读

## 6. 系统调用与命令

| 调用号 | 名称 | 参数 |
| --- | --- | --- |
| 22 | `SYS_MOUNT` | path, dev, fstype |
| 23 | `SYS_UMOUNT` | path |
| 24 | `SYS_MOUNTS` | `user_mount_t[]`, cap → active 数量 |

`user_mount_t` 为 96 字节（`path[64]`、`dev[16]`、`fstype[12]`、
`active`、`readonly`、2 字节填充），Rust 侧镜像在 `apps/src/fs.rs`。

```text
nsh> drives
MOUNT POINT          DEVICE       FSTYPE      MODE
/                    root         novusfs     rw
/disk1               disk1        novusfs     rw

nsh> mount usb0 /media/usb0
nsh> ls /media/usb0
nsh> umount /media/usb0
nsh> mount -a            # 重放 mounts.json
```

文件管理器磁盘页提供 `/Users/alice`、`/media`、`/.novusfs` 快捷入口；
设备管理器 `/dev` 列表在驱动名后附逻辑设备名，如 `ahci00 [disk0]`。

## 7. 构建校验与已知限制

```bash
make iso
make check-rootfs          # scripts/check_rootfs.py：三套镜像、435 项断言
scripts/font_smoke.sh      # QEMU 串口冒烟，检查 [FONT]/[MOUNT]
```

`scripts/novusimg.py` 提供 NovusFS / FAT / ISO9660 的只读解析器，
`scripts/inspect_img.py`、`_extract_sys.py`、`_verify_font.py` 等按路径查找，
不再假设「inode 2 就是 font.bin」。

限制：

- FAT/ISO 上的长名只在 ISO Joliet 树保留；FAT 侧仅 8.3 别名。
- 不实现 NTFS 后端，也不实现运行时热插拔事件；挂载发生在启动与显式
  `mount -a` / `mount`。
- 挂载表固定 8 项，每种只读后端最多 2 个并发实例。
- 4Kn 设备通过整块 bounce buffer 访问；FAT 仅支持 512 字节扇区的卷。
