## 一、改了什么

| 文件 | 改动 | 目的 |
| --- | --- | --- |
| `kernel/blkdev.h` | 新增 `blk_flush_fn` / `blk_power_fn` / `blk_power_state_fn`、电源状态常量、`last_active_tick`、`power`、`power_irq_safe`，以及 `blkdev_flush/powerdown/power_state` 内联封装与 `blkdev_idle_sweep/standby_all` 声明 | 块层统一暴露「刷缓存」「停转」「查电源状态」三个能力，后端按需实现 |

| `kernel/nvme.c` | `NVMe FLUSH`、`cdw12 = nlb-1` 多块传输、512B 块一次 8 块 | NVMe 缓存落盘与吞吐 |
| `kernel/usb.c` | `SYNCHRONIZE CACHE(10)`、`START STOP UNIT(0x1B)` | U 盘缓存落盘；旋转介质停转（`power_state` 未实现，SCSI MODE SENSE 属后续） |
| `fs/novusfs/super.c` | 主、备超级块写完后 flush | 掉电后两份超级块都可恢复 |
| `fs/novusfs/wal.c` | `wal_commit` 追加 TX_COMMIT 后 flush，失败即返回 -1 | commit marker 真正落盘，事务语义闭合 |
| `kernel/sched.c` | 时钟 tick 每 100 tick（1 秒）调用一次空闲扫描；`sched_park()` 与内核 idle 循环也扫描 | 桌面常驻任务让 idle 循环永不可达，tick 是唯一可达的周期点 |

## 二、休眠怎么工作

- 默认空闲阈值 **120 秒**，`blkdev_set_idle_timeout(seconds)` 可改，传 0 关闭。
- 触发点三处：时钟 tick（每秒）、任务 park 等待 IPC 时、内核 idle 循环。
- 判定条件：有 `powerdown` 实现、非只读、非 boot-only、当前状态 ACTIVE、且距上次传输超过阈值。
- 停转顺序：先 `blkdev_flush` 落缓存，再发 STANDBY；成功后置 STANDBY，之后不再重复发命令。
- 下一笔读写自动把盘唤醒（ATA 硬件行为），上层无需显式唤醒。
- USB 大容量设备标记 `power_irq_safe = 0`，只会从任务上下文被扫描 —— 它的 Bulk-Only 状态机是多步的，不能在中断里插入命令。
- NVMe 不实现 `powerdown`：NAND 没有「停转」语义。

## 三、验证（云主机 QEMU + OVMF，`-accel tcg`）

两套控制器、各自从零启动到自检通过。

**IDE（PIIX3，`-machine pc -drive if=ide`）**

```
[IDE] disk ide0 capacity 0x0000000000020000 sectors, lba48=0x0000000000000001
[BLK] idle spin-down after 0x0000000000000078s
...
[BLK] spun down ide0 after 0x0000000000000078s idle
```

**AHCI/SATA（q35）**

```
[AHCI] controller cap 0x00000000C0141F05 ports 0x000000000000003F
[AHCI] LBA 0 DMA read PASS
[AHCI] disk ahci00 controller ... capacity 0x0000000000020000 sectors, block 0x200 bytes
[BLK] idle spin-down after 0x0000000000000078s
...
[BLK] spun down ahci00 after 0x0000000000000078s idle
```

两场景共同点：`[NOVS] === selftest PASSED ===` 照常通过，停转只打印一次（`power` 已转 STANDBY，扫描不再重复发命令），tick 持续增长到 27000+ 无卡死、无 `[TRAP]`。

Windows 本机与云主机双端 `make clean && make` 均 0 error（warning 均为既有：`net_http.h` 注释、rust jobserver、`net_tcp.c` 未用变量）。

## 四、没做 / 未验证的部分

1. **关机与重启路径未端到端验证**：需要从桌面点关机才会走 `power_off()`，本轮没有做 VNC 点击。代码路径本身已编译进镜像。
2. **USB 的 `power_state` 未实现**：需要 SCSI `MODE SENSE(0x1A)` page 0x1A，`blkdev_power_state()` 对 USB 返回 UNKNOWN。
3. **AHCI 的 `power_state` 主动置空**：`CHECK POWER MODE` 是 PIO 命令，AHCI 只能用 PRDT/DMA 搬数据，发出去会「完成但没数据」，把旧缓冲当成答案。宁可不查询，也不上报不可信状态。
4. **IDE 的 `power_state` 在 QEMU 上拿不到数据**：QEMU 对该命令不置 DRQ，实现里用 20 ms 短超时快速返回失败 → UNKNOWN，不会卡住。
5. **仍未实现的驱动能力**：AHCI NCQ 与多 command slot、IRQ 完成、NVMe PRP list 与更深队列（现 4）、IDE DMA（现在纯 PIO）、USB BOT reset recovery、ATAPI 光驱。
6. **休眠阈值无用户入口**：设备管理器目前不显示盘的电源状态，也没有「立即停转」按钮或命令。需要的话下一步接到 `kernel/devtab.c`。

## 五、复现命令

云主机（已有交叉工具链）：

```bash
export PATH="/home/user/local/usr/bin:/home/user/.cargo/bin:$PATH"
make clean && make -j2 && make disk-img out/wallpapers.pkg
```

启动（IDE）：`-bios OVMF.fd -drive file=out/novus-disk.img,format=raw,if=ide,file.locking=off -accel tcg`
启动（AHCI）：机器改 `-machine q35`，其余相同；q35 下 OVMF 可能落到 UEFI Shell，手动执行 `fs0:\EFI\BOOT\BOOTX64.EFI`。
串口 `-serial file:<log>`，等待 ≥120 秒空闲即可看到 `[BLK] spun down`。

Windows 本机：`build-win.cmd -j8` → `build-win.cmd disk-img out/wallpapers.pkg`（本机无 QEMU，只能构建，不能启动验证）。
