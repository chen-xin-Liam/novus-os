# 真机验证卡 · USB（镜像 9D3BD6F317BA / U-54…U-56）

这一轮修掉的是一个**能解释"设备认出来了但鼠标不动"的确定 bug**：完成事件只按 endpoint 认领，没按 slot 认领。键盘和鼠标都用 interrupt IN EP1，于是先被轮询的那台把另一台的报告吃掉。QEMU 上已经把两个方向、混拓扑、两只鼠标、拔插重插全部跑通，但真机仍然只有这一次开机才能证明。

## 这一版改了什么（只列会影响真机行为的）

1. **U-54 事件归属带 slot**：`usb_defer_push/take/drop` 与三处 `event_pop()` 消费点都改成 `(slot, dci, epid)` 三键匹配。此前"鼠标枚举成功、`[INP] usb mice=0`、光标不动、日志里却有一份 report"就是它。
2. **U-55 Stop Endpoint 后等 Stopped 事件**：`ep0_recover()` 先等 `code==26` 的 transfer event（50 ms 预算）再改 dequeue 指针；等不到就记 `g_ep0_rst`，并在报告页 `rsv=` 后写 `/rst`。
3. **U-56 报告页加 `crq=`**：`chk=` 后面多两个数（CRCR 低 32 位 / `cmd_phys` 低 32 位），两值相等即证明命令环就是我们在写的那条。
4. 上一版已在仓库里、这次一并带上：U-49 热插拔成功即强制 flush、U-50 报告页退出后整屏重绘、U-51 启动竞态日志重试、U-52 时基自检 `tmb`/`tm`、U-53 hub 子端口运行期轮询。

镜像：`C:\novus\out\novus-desktop.img`，sha256 前 12 位 **9D3BD6F317BA**，67,108,864 B。
已写入 SanDisk U 盘（disk 4），写后回读 sha256 一致（`C:\msys64\tmp\flash3.log`）。

## 开机怎么试

1. 从这支 U 盘启动，等桌面出现（先有 7 帧开机动画，再进内核）。
2. **先什么都不插**，用机器自带的 USB 鼠标在桌面上划几下：
   - 指针跟着动 → 这一版在真机上生效了，把"能用了"告诉我就行，剩下的按清单继续收尾。
   - 指针不动 → 拍照（见下），别拔盘。
3. 如果鼠标在扩展坞 / hub 上：**开机后再把它插进 hub**，等 3–5 秒，再划。运行期插入现在由 U-53 的子端口轮询接管，最多约 1–2 秒一轮。
4. 键盘顺手验一下：点开设置窗口，按 `a`，能输进去就说明键盘的 8 字节报告没有被鼠标抢走（正是 U-54 的反向验证）。

## 拍照要拍的那一页

如果这一版**没有**把日志写进 U 盘，开机会先出现整屏「Novus OS · 启动诊断」并停留 45 秒——把这一屏完整拍下来即可。最关键的几个字段：

| 字段 | 看什么 |
| --- | --- |
| `chk=f` | 四比特全 1 = 控制器寄存器仍描述着我们建的环；`chk=d` 且 `crq` 两值不等 = CRCR 不是这条环 |
| `crq=xxxxxxxx/xxxxxxxx` | 两个数相等 = 命令环没问题（U-56 新增） |
| `rsv=0/0` 或 `rsv=…/rst` | 出现 `/rst` = Stop Endpoint 在 50 ms 内没回 Stopped（U-55） |
| `tmb=1 tm=000a` | 毫秒预算可信；`tmb=0` = 时基死了，所有超时都无意义 |
| `hse=` / `try=` | `hse` 非 0 = 曾被清掉 HSE；`try` ≥1 = 靠第二/三遍阶梯才枚举成功 |
| `rs=` / `at=` / `ec=` | 每个根口的状态与枚举走到第几步、描述符传输完成码 |

## 日志能落盘时怎么读

U 盘这次仍插在机器上就直接读（需要管理员）：

```powershell
pwsh -File C:\novus\tools\read-usblog\read-usblog.ps1 -Disk 4
```

也可以对镜像文件读：`-Image C:\novus\out\novus-desktop.img`。日志是裸扇区（LBA 51200 起 257 扇区），不依赖文件系统，所以"读到文本"本身就证明那块盘在这次运行里被我们成功枚举并写入过。

## QEMU 上已经验过的（供对照，不是真机结论）

- hub 键盘开机 + 鼠标运行期插口 2：`HID report addr=3 bytes=4`，光标 (512,256)→(698,373)。
- 鼠标开机 + 键盘运行期插口 2：`mouse_move 80 60` 得 `addr=2 bytes=4`、光标 592,316；`sendkey a` 得 `addr=3 bytes=8`、`[NDQ] pop type=4 key=97`。
- 根口鼠标 + hub 键盘 + 根口 U 盘：两设备各自 4/8 字节报告，日志 `boot log -> usb00`、文字段 38 扇区非零。
- 两只鼠标 + 键盘，12 次 `mouse_move 20 10`：光标 512,256→752,376（240/120 一次不丢）。
- 运行期拔出鼠标、插到另一个 hub 口：新设备拿新 slot（3→4），报告照常，光标 552,276→582,306。
- 诊断页：`chk=f crq=00372000/00372000`、`tmb=1 tm=000a`、`hse=0 try=0`。

## 仍未验证（如实）

- 真机没有任何一轮读数来自本镜像；以上全部是 QEMU 6.2（`qemu-xhci` + 全速 `usb-hub`）。
- 高速 hub 下 LS/FS 子设备的 TT 路径无法在 QEMU 构造。
- `ep0_wait_stopped()` 的 50 ms 在 Intel PCH 上够不够，未知；不够时页面会写 `/rst`。
- `usb_defer` 表只有 8 个槽，三台以上 HID 同时被打断时有被覆盖的可能。
- 源码全部未提交（分支 `b/boot-anim`，HEAD `3814a0d`，PR #19）。
