# Novus 应用图形化开发指南

这篇讲的是：在 Novus OS 里从零写一个**带窗口的程序**，画进自己的客户区，收鼠标和键盘，然后把它挂进系统镜像里能被点开。配套的可运行示例是 `apps/src/bin/hello.rs`，本文每个结论都能在那份代码里对上。

## 1. 应用是什么

内置应用不是普通 ELF，也不是加载器从盘上读的：它们是 **no_std 的 Rust 程序**，被编成扁平二进制，链接在固定的 `0x400000`，再以 C 数组的形式**嵌进内核镜像**。开机后内核 `nuc_spawn_blob()` 把这段字节按原地址映射进一个新进程，`_start` 就是入口。

由此推出几条硬规则：

- 没有 `main`，没有 Rust 运行时，没有分配器，没有 `std`。`#![no_std] #![no_main]` 是必需的。
- 入口签名固定：

```rust
#[no_mangle]
pub extern "C" fn _start() -> ! { ... }
```

- 退出就是 `sys::exit(code)`，没有析构、没有 flush，别指望退出时还能画一帧。
- 只能用 `novus_apps` 这个 crate 暴露的东西：`sys`（系统调用）、`ipc`（按名字找端口、收发消息）、`wm`（窗口客户端）、`ui`（配色与常用控件）、`fs`/`sinfo`（文件与系统信息）。

## 2. 一帧是怎么画上屏的

关键点：**应用不碰帧缓冲**。你发给窗口管理器（WM）的是一串"显示列表"命令，WM 在自己的合成缓冲里重放这串命令，只裁剪到你窗口的矩形内，然后统一上屏。这样做的好处是每个应用都被关在自己的窗口里，画不到别处去。

一次重画的完整动作：

```rust
win.clear();                       // 清空这一帧的显示列表（不擦屏幕）
win.fill(0, 0, CW, CH, ui::bg());  // 追加一条"填充矩形"
win.text(20, 40, ui::text(), "hi");// 追加一条"文本"
win.invalidate();                  // 提交：WM 重放并上屏
```

几条必须记住的语义：

- **坐标原点是你客户区的左上角**，`(0,0)` 不是屏幕左上角。标题栏由 WM 画在你的上方，所以 `create()` 里的高要给到"客户区高 + `wm::FRAME_H`"，宽多给 2 像素的下/右边框（`CW + 2`、`CH + wm::FRAME_H`，和 fileman 一致）。
- **每帧有预算**：单窗口一帧最多 **120 个 shape + 160 条文本**（`wm::MAX_SHAPES` / `MAX_TEXTS`）。超了 WM 会**静默截断**，表现就像"画到一半少了东西"，不是崩溃。列表、表格这类要画的多的界面，只能画可见行。
- **`clear()` 之后什么都不画就 `invalidate()`，不会把屏幕清空**。这是刻意修的：空闲重绘不该把已有内容抹掉。要清屏必须至少画一条覆盖全客户区的填充。
- **单条文本最多 96 字节**（`wm::TEXT_MAX`，含中文时按 UTF-8 算，约 32 个汉字），窗口标题最多 24 字节。超长会被截断到不切断码点的位置，不是报错。
- 画到客户区外的命令会被 WM 裁掉，不会跑到别人窗口上，但也没有任何提示。

## 3. 最小骨架

完整代码见 `apps/src/bin/hello.rs`，结构就是四步：

```rust
#[no_mangle]
pub extern "C" fn _start() -> ! {
    sys::write(b"[APP] hello up\n");                       // 1. 串口打个招呼

    let Some(wm_port)  = ipc::lookup(wm::PORT_NAME) else { sys::exit(1) };
    let Some(sys_port) = ipc::lookup(sinfo::PORT_NAME) else { sys::exit(2) };

    let Some(mut win) = wm::Win::create(                   // 2. 建窗口
        wm_port, 120, 180,                                 //   屏幕坐标
        CW as i32 + 2, CH as i32 + wm::FRAME_H,            //   宽/高（含边框）
        ui::l("示例应用", "Sample app"),
    ) else { sys::exit(3) };

    ui::init(sys_port);                                    // 3. 主题色/语言就绪
    let mut accent = ui::accent();
    let mut st = State { count: 0 };

    draw(&mut win, &st, accent);                           //    先画第一帧

    loop {                                                 // 4. 事件循环
        let mut redraw = false;
        while let Some(ev) = win.next_event() {
            match ev {
                wm::Ev::Close => { win.destroy(); sys::exit(0); }
                wm::Ev::Mouse(m) if m.kind == wm::MOUSE_DOWN
                                  && m.button == wm::BUTTON_LEFT => {
                    if ui::inside(INC_RECT, m.x, m.y) { st.count += 1; redraw = true; }
                    else if ui::inside(QUIT_RECT, m.x, m.y) { win.destroy(); sys::exit(0); }
                }
                wm::Ev::Key(k, _) if k == wm::KEY_ESC => { win.destroy(); sys::exit(0); }
                _ => {}
            }
        }
        if ui::poll(sys_port) { accent = ui::accent(); redraw = true; }
        if redraw { draw(&mut win, &st, accent); }
        sys::yield_now();
    }
}
```

`ui::l("中文", "English")` 按系统语言选串；`ui::poll()` 返回真表示主题或语言变了，需要整体重画。空转时 `sys::yield_now()` 让出 CPU，别在 receive 上忙等。

## 4. 能画什么

`wm::Win` 是最底层的一层，命令很少但够用：

| 调用 | 作用 |
| --- | --- |
| `fill(x, y, w, h, color)` | 实心矩形 |
| `frame(x, y, w, h, color)` | 一像素描边 |
| `round_fill(x, y, w, h, r, color)` | 圆角实心（`r` 最大 255） |
| `round_frame(x, y, w, h, r, color)` | 圆角描边 |
| `shape(op, x, y, w, h, color)` | 直接指定图元（`OP_FILL`/`OP_FRAME`/`OP_HLINE`/`OP_VLINE`/`OP_CIRCLE`） |
| `text(x, y, color, s)` | 正文文本，单行，96 字节上限 |
| `text_big(x, y, color, s)` | 大号文本（标题、数字） |

`ui` 是在这层命令之上拼好的界面语言，Novus 的应用应该优先用它，视觉才一致：

| 组件 | 用法 |
| --- | --- |
| `ui::page(win, cw, ch, title, subtitle)` | 整页骨架：底色、大标题、副标题、分隔线 |
| `ui::shell(win, cw, ch, title, accent)` | 紧凑版页眉（34 px 带） |
| `ui::card(x, y, w, h)` | 圆角卡片 + 发丝边框 |
| `ui::section(x, y, label)` / `ui::divider(x, y, cw)` | 小节标题 / 分隔线 |
| `ui::button(x, y, w, h, label, color)` | 主按钮，返回矩形，便于命中测试 |
| `ui::ghost(x, y, w, h, label)` | 次按钮（描边） |
| `ui::nav(x, y, nw, label, selected)` | 侧栏导航项 |
| `ui::progress(x, y, pw, permille)` | 进度条，千分制 |
| `ui::empty(x, y, label)` | 空状态提示 |
| `ui::Menu` | 右键/下拉菜单：`set` 项 → `open` → `click` 返回 action 号 → `draw` |

颜色不要写死 RGB：取 `ui::bg()` / `card_bg()` / `text()` / `dim()` / `line()` / `accent()` / `good()` / `warn()` / `danger()`，亮暗主题和强调色就都跟着系统走。需要量文本宽度用 `ui::width()` / `ui::width_big()`，截断用 `ui::fit()`。

## 5. 事件

`win.next_event()` 取一条事件，队列空时返回 `None`：

- `Ev::Mouse(MouseEvent { x, y, kind, button, mods, .. })`：`x/y` 是**客户区坐标**；`kind` 取 `MOUSE_MOVE` / `MOUSE_DOWN` / `MOUSE_UP`；`button` 是掩码 `BUTTON_LEFT` / `BUTTON_RIGHT` / `BUTTON_MIDDLE`。
- `Ev::Key(key, mods)`：字符键给 ASCII 码，功能键给 `KEY_ESC` / `KEY_UP` / `KEY_DOWN` / `KEY_LEFT` / `KEY_RIGHT` / `KEY_DELETE` / `KEY_HOME` / `KEY_END` / `KEY_TAB` / `KEY_ENTER` / `KEY_BACK`。
- `Ev::Focus(on)`：窗口获得/失去焦点。
- `Ev::Close`：用户点了标题栏的关闭框。**必须**在这里 `win.destroy()` 再 `sys::exit(0)`，否则窗口留着、进程不死。

焦点规则：点击窗口的可见区域，或者新窗口创建，才会拿到键盘。所以"按 Esc 没反应"通常是焦点在别的窗口上，不是按键没送到。

## 6. 进程层面的约束

- 同名应用**只允许一个实例**：已经在跑再启动会拿到 `APPS_ERUNNING`，现有代码的处理是把它窗口提到前面而不是报错。
- 除 `session`、`setup` 两个引导程序外，启动应用要求**已登录会话**，否则返回 `APPS_EAUTH`。
- 崩溃（panic）不是杀内核：panic handler 打一行 `[APP] panic` 然后用退出码 3 结束进程，任务管理器里能看到这一行和这个码。自己定的退出码（示例里的 1/2/3 = 找不到 WM 端口 / 找不到 sysinfo 端口 / 建窗口失败）在排查时很有用。
- 串口第一行 `[APP] xxx up` 是约定，真机没屏可看的时候就靠它。

## 7. 把它挂进系统

三步，缺一步就启动不了。以 `hello` 为例，全部改动都是**追加在末尾**——`/apps` 的显示顺序和 spawn 用的索引都吃 `kernel/apps.c` 的表位置，插在中间会挪动已有应用。

1. `apps/Cargo.toml` 加一个产物：

```toml
[[bin]]
name = "hello"
path = "src/bin/hello.rs"
```

2. `Makefile` 的 `APPS_NAMES` 末尾补名字（构建脚本据此编 blob 头）：

```make
APPS_NAMES  := fileman taskman settings netman session setup nsh devmgmt novusd dwm hello
```

3. `kernel/apps.c` 的 `g_apps[]` 表尾加一行，符号名由构建生成（`k_app_<name>`）：

```c
{"hello", k_app_hello, &k_app_hello_len},
```

然后 `make`（或 `C:\msys64\tmp\build_main.cmd`）。构建日志里会有一行 `apps: hello 52436 bytes`，这个数字是扁平镜像的实际大小；应用上限来自 `nuc` 的映射窗口，目前内置应用都在 130 KiB 以内。

**怎么启动**：桌面上点"文件管理器"，进"应用"视图，选中 `hello` 按 Enter（`sinfo::spawn_name` 走的就是 `apps_launch_name`）。它不占 dock 图标的坑——dock 那几个是 `nd_demo.c` 里写死的六项。

**怎么验证**（QEMU）：

```sh
make disk-img            # 产物 out/novus-desktop.img
qemu-system-x86_64 ... -serial file:serial.log
```

串口里应该依次看到 `[APPS] launching hello (0x… bytes)` 和 `[USER] [APP] hello up`，窗口出现在 (120,180)。改窗口内容后如果只在 `[NWM]` 里看到 `s=0 t=0`，说明你这一帧没画东西就提交了。

## 8. 常见坑

- **画了但不显示**：先查是不是 `invalidate()` 前没 `clear()`（旧帧残留叠加），或者这一帧命令数超了 120/160 被截断。
- **文字被吃掉半截**：单条文本 96 字节上限，长句子自己拆成多条 `text()`，或者用 `ui::fit()` 先截。
- **窗口比内容矮**：`create()` 的高要 `CH + wm::FRAME_H`，宽要 `CW + 2`；少给就会挡掉最底一行。
- **点击命中错位**：鼠标事件坐标是客户区坐标，命中矩形要和绘制用同一组常量（示例里的 `INC_RECT` 就是为此抽出来的）。
- **关不掉**：`Ev::Close` 里没 `sys::exit`，进程会一直活着，再启动就被判 `ERUNNING`。
- **CPU 空转 100%**：循环末尾漏了 `sys::yield_now()`。

## 9. 往深里走

- 需要读文件、列目录：`fs`（NovusFS）和 `sinfo`（内置虚拟视图），fileman 是完整范例。
- 需要多窗、子窗、模态：`Win::create_ex(..., wm::CREATE_MODAL)`；模态窗会扣住指针和键盘，属性对话框就是这种。
- 需要自己合成、贴图、缩略图：`surface_create` / `flip` / `blt_submit` / `thumbnail` 这套（Mini-DWM 的重定向路径），`apps/src/dwm/` 里有实现。
- 想要硬件加速：见 `docs/GPU 硬件加速路线图.md`，P3 之后 GPU2D 接缝一旦接通，`wm` 的填充/圆角命令会下沉到硬件 blit，应用侧代码不用改。

## 11. 系统应用现在住在 `/Novus/bin`（NUC 文件，不是内核里的数据）

从这一版起，图形系统应用的“本体”是文件系统里的一个 `.nuc` 可执行文件，内核里那份只是备份。

- 开机时 `sysapps_seed()`（`kernel/sysapps.c`）在根卷挂好后跑一次：把每个内嵌 blob 用 `nuc_pack_blob()` 打成 NUC 镜像，写到 `/Novus/bin/<name>.nuc`。文件已存在且逐字节相同就跳过（`kept`），内容不同就替换，介质拒写就放弃——**内嵌镜像永远是兜底**。
- 写盘走 `novusfs_write_direct`：这些镜像每个几十 KB，加起来比 256 KiB 的 WAL 环大得多，一次性工厂写入不需要回滚。目录项本身仍走日志事务，所以文件要么完整出现，要么根本没有。
- 启动时 `apps_launch()` 先 `sysapps_spawn()`（读 `/Novus/bin/<name>.nuc` → `nuc_load`），成功才算跑起来；文件缺失或介质只读才退回 `nuc_spawn_blob()`。串口里 `[APPS] image from /Novus/bin` 就是“这次跑的是文件”。
- `/Novus` 是系统树：`fs/vfs_mount.c` 的 `vfs_mount_unlink_path` / `vfs_mount_rename_path` 对 `/Novus` 前缀一律返回 -1，普通用户路径删不掉也改不了名。安装器走的是 `novusfs_*` 直调，不受这条保护影响。

所以写一个新系统应用，还是第 7 节那三步（`apps/Cargo.toml` 加 `[[bin]]`、`Makefile` 的 `APPS_NAMES` 加名字、`kernel/apps.c` 表尾加一项），不需要再自己写安装逻辑：开机 seed 会把它变成 `/Novus/bin/<name>.nuc`，启动就走文件。

验证（串口）：

```
[SYSAPP] wrote /Novus/bin/fileman.nuc (0x00010E34 bytes)
[SYSAPP] seed done: written=0xB kept=0x0 failed=0x0
[APPS] image from /Novus/bin
```

两条注意：

- 别在系统树里手改 `.nuc`：下次开机 seed 比对不一致会把它覆盖回内核里的那份。想换程序就改 `apps/src/bin/` 源码重新构建。
- 只读介质（ISO、刻死的 U 盘）上 seed 写不进去，日志是 `cannot write …` 或 `is not writable`；此时全部应用仍从内嵌镜像启动，功能不缺。
