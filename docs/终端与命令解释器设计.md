# Novus OS 终端与命令解释器（nsh）设计文档

> 阶段：M2 基座 / 第一阶段交付
> 状态：已实现（内核 syscall + 用户态 shell 引擎 + 终端窗口 + 桌面入口）

本文档描述 `nsh` 交互式终端 shell 的设计边界、命令清单、实现要点与已知限制。它刻意与 Novus 已有的 Windows 风格 GUI（文件管理器、设置、任务管理器、桌面外壳）**解耦**：终端永远使用单根 `/`、POSIX 语义；cmd.exe 兼容别名（`dir`/`copy`/`del` 等）默认关闭，是可选项。

---

## 1. 架构边界

| 层级 | 技术 | 说明 |
|------|------|------|
| 内核 | C（`kernel/trap.c`、`fs/vfs.*`、`fs/novusfs/*`） | 新增 `unlink`/`rename` 两个 syscall |
| 用户态 | Rust（`apps/`，`no_std`、无分配器、目标 `x86_64-unknown-none`） | `shell` 模块 + `nsh` 二进制 |
| 桌面 | C（`graphics/nd_demo.c`、`nvgui.c`） | 开始菜单 / 磁贴 / 任务栏入口 + `NG_ICON_TERM` 图标 |

关键不变量：

- **终端只认真实 `/` 路径，绝不识别盘符或 `vol:` 友好名。** 用户输入的相对路径一律基于 shell 维护的 `cwd` 在内核态之前被解析成绝对路径（见 `shell/path.rs`）。GUI 的「友好卷名」语义与内核、终端互不污染。
- **无 fork/exec。** 没有进程模型支撑并发管道，因此 `|` 与 `$(...)` 采用「左命令完整输出进固定缓冲、再作为 stdin 喂右命令」的顺序捕获实现。这是第一阶段有意的简化，后续随进程模型增强可升级为真正并发管道。
- **cmd 别名包默认关闭。** `Shell.cmd_aliases` 为 `false`；其开关持久化（OOBE）留待后续阶段。开启后，`dir→ls`、`copy→cp`、`del→rm`、`move→mv`、`type→cat`、`cls→clear` 生效。

## 2. 内核能力补齐

### 2.1 新增 syscall

| 编号 | 名称 | 行为 |
|------|------|------|
| 20 | `SYS_UNLINK` | 删除文件或**空**目录；目录非空时由 `vfs_unlink_path` 拒绝 |
| 21 | `SYS_RENAME` | 移动 / 重命名；后端不支持 `rename` 时返回 -1 |

两个 syscall 均复用既有 `user_path()` 拷贝与 `session_logged_in()` 校验，保持安全边界。

### 2.2 VFS 抽象

- `vfs_fs_t` 新增 `rename(fs, olddir, oldname, newdir, newname)` 操作字段；`NULL` 表示后端不支持（如 ext4 适配器），`vfs_rename_path` 遇 `NULL` 返回 -1。
- `vfs_unlink_path(fs, path)`：原地拆分父目录 + 叶子 → `stat` 判断类型 → 目录需先确认无条目再删（NovusFS 无 `.`/`..` 条目，所以任一子项即视为非空）。
- `vfs_rename_path(fs, old, new)`：拆分源/目标为（目录, 名）后调用后端 `rename`。

### 2.3 NovusFS 的 rename 事务布局

`fs/novusfs/dir.c` 的 WAL 注释明确「单事务内同一数据块只记录一次」。若在同一事务里对一个目录块既 `dir_add` 又 `dir_remove` 会丢记录，因此 `novusfs_rename` 拆为三步，每步独立事务：

1. （若目标已存在）单独事务删除目标条目；
2. 事务中添加新名并提交；
3. 事务中删除旧名并提交。

目录的**数据块**与目录**inode 表块**是不同的块，所以「dir_add/dir_remove + inode_write_tx」在同一事务内不会产生重复块记录。崩溃落在两步之间最多造成文件短暂「双名」（可恢复），不会丢失数据。

`>` 重定向的截断复用 `unlink` + `open(O_CREAT)`，`>>` 追加则先读旧内容再整体写回，无需新增 truncate syscall。

## 3. 用户态 shell 引擎

源码位于 `apps/src/shell/`：

| 文件 | 职责 |
|------|------|
| `path.rs` | `normalize(cwd, input) -> [u8; PATH_MAX]`：相对/绝对、`.`/`..`（词法折叠，因 VFS 无 `..` 条目）、`~/`→`/` |
| `parse.rs` | 分词状态机：单/双引号、转义、`$VAR`、`$(...)`（递归调用 `run_subst` 捕获）、glob `*`/`?`、重定向 `< > >>`、管道 `\|`、分隔符 `; && ||` |
| `mod.rs` | `Shell` 状态机（`cwd`、`vars[32]`、`aliases[16]`、`history[64]`、`cmd_aliases`、`last`）、`run_line` / `run_statement`、`Sink` trait、`Capture` 缓冲、`read_file` / `write_file` |
| `cmds.rs` | 内置命令表（命令名→函数指针）与所有内置实现；`run()` 负责别名展开、内置查找、可选 cmd 别名、外部命令经 `sinfo::spawn_name` 启动 |

`Sink` trait 只有两个方法：`write(&[u8])`（必需）与 `clear_screen()`（默认空实现）。终端窗口与 `$(...)`/管道捕获缓冲都实现它，因此同一套内置命令既能在屏幕上输出，也能被管道 / 命令替换捕获。

无分配器约束：所有行内缓冲、历史、环境变量、参数向量、管道中间缓冲均用固定大小数组（见 `MAX_ARGS=40`、`SCRATCH=1536`、`WORD_MAX=256`、`Capture.buf=[u8;4096]`）。`$(...)` 嵌套深度上限 3，防止栈溢出。

## 4. 终端窗口 `nsh`

`apps/src/bin/nsh.rs` 是一个独立的 `no_std` 二进制，由桌面外壳经 `sinfo::spawn_name(wm_port, "nsh")` 启动（与其他内置应用一致）。

- **布局**：标题栏由 novus-wm 统一绘制（标题「终端」+ `NG_ICON_TERM` 图标）；文本主体为 `72×26` 字符栅格（scale=2，字宽 12px、行高 16px），左上起排，自动滚动到末行。
- **外观**：近黑背景（`0x0E1117`）、浅灰等宽文本（`0xD4D4D4`）；提示符 `<accent>user@novus</accent>:<dim>路径</dim> $ `，输入随键入实时回显。严格复用 `ui.rs` 主题令牌（`accent()` 取当前桌面主题强调色），与现有 Fluent 桌面一致，但关闭圆角卡片感、强调可读性。
- **交互**：行编辑（左右光标移动、退格、Home/End、Delete）、上/下历史回溯、Ctrl+C 中断当前行（回显 `^C` 后清空）、Ctrl+L 清屏；`Enter` 回显命令行并将输出经 `Sink` 写入滚动缓冲（环形定长数组，无动态增长）。
- **修饰键**：`wm.rs` 的 `Ev::Key` 由 `Ev::Key(u32)` 扩展为 `Ev::Key(u32, u8)`，携带 `mods`，并同步 `session.rs`/`setup.rs`/`fileman.rs` 三处匹配，使终端能识别 Ctrl 组合键。

## 5. 命令清单（第一阶段）

| 命令 | 支持选项 | 说明 |
|------|----------|------|
| `ls` | `-l -a -h` | 列表；`-l` 长格式（模式/大小/类型），`-a` 含点文件，`-h` 人类可读大小 |
| `cd` | — | 切换目录（`~` 视为 `/`）；无参数回 `$HOME` |
| `pwd` | — | 打印当前绝对路径 |
| `cat` | — | 拼接输出文件，无参数则从 stdin 输出 |
| `echo` | `-n` | 回显，`-n` 不换行 |
| `mkdir` | `-p` | 创建目录；`-p` 递归创建父目录 |
| `rmdir` | — | 删除空目录 |
| `rm` | `-r -f` | 删除；`-r` 递归（shell 驱动，内核拒绝非空目录），`-f` 静默 |
| `cp` | `-r` | 复制文件 / 目录（目标为目录时复制到其下） |
| `mv` | — | 移动 / 重命名（经 `rename`） |
| `stat` | — | 打印大小与类型 |
| `env` / `export` / `unset` | — | 环境变量查看 / 设置 / 删除 |
| `clear` | — | 清屏（请求终端清滚动缓冲） |
| `help` | — | 列出内置命令名 |
| `history` | — | 列出历史命令 |
| `true` / `false` | — | 退出码 0 / 1 |
| `whoami` | — | 输出 `user` |
| `which` | — | 区分内置 / 已注册 app / 未找到 |
| `touch` | — | 创建或更新空文件 |
| `wc` | — | 行 / 词 / 字节计数 |
| `head` / `tail` | `-n N` | 前 / 后 N 行 |
| `tree` | — | 递归缩进显示目录树 |
| `alias` | — | 设置 / 列出别名 |
| `drives` | — | 列出挂载（单根 `/`，占位） |

**分隔符**：`;` 顺序执行，`&&` 前一条成功才继续，`||` 前一条失败才继续。
**重定向**：`< file`、`> file`（截断）、`>> file`（追加）。
**展开**：`$VAR`、`$(cmd)`（顺序捕获后替换）、glob `*`/`?`（在结果目录上 `readdir` 枚举）。
**外部命令**：内置未命中时，尝试以已注册 app 名经 `sinfo::spawn_name` 启动；仍失败则报 `<name>: command not found`（退出码 127）。

## 6. 已知限制（第一阶段）

1. **管道与 `$(...)` 为顺序捕获，非并发进程。** 左命令必须完全结束后其输出才作为右命令的 stdin；不适合流式或相互阻塞的管道。`help` 已注明。
2. **无真正的 fork/exec。** 所有「命令」要么是内置，要么是已注册应用（同一套 app 表）；不存在任意 ELF 执行。
3. **`rename` 仅在 NovusFS 根支持。** ext4 等外挂后端返回 -1，shell 报「文件系统不支持」。
4. **目录删除需显式递归。** `rm -r` 由 shell 自顶向下枚举删除，内核 `unlink` 本身拒绝非空目录，保证删除行为可控。
5. **glob 不跨目录、不处理隐藏匹配细节。** 单段 `*`/`?` 在所在目录内展开。
6. **行宽按像素计。** 一行 864 px；ASCII 6 px、半角 8 px、全角 16 px，换行只发生在码点边界。光标位置、滚动缓冲折行和退格/左右键都按码点与绘制宽度推进，不再假设「1 字符 = 1 列 = 6 px」。

## 7. 构建与接线

- `kernel/apps.c`：`g_apps[]` 末尾追加 `{"nsh", k_app_nsh, &k_app_nsh_len}`（不移动既有索引；spawn 按名查找，故顺序变更安全）。
- `Makefile`：`APPS_NAMES` 追加 `nsh`，由 `xxd` 生成 `k_app_nsh` 符号写入 `apps_blobs.h`。
- `apps/Cargo.toml`：显式 `[[bin]] name="nsh" path="src/bin/nsh.rs"`（cargo 也会自动发现 `src/bin/nsh.rs`）。
- `graphics/nd_demo.c`：开始菜单、桌面右侧磁贴列、任务栏快速启动区各新增「终端」入口，统一回调 `on_launch_terminal` → `launch("nsh")`。
- `graphics/nvgui.c` / `nvgui.h`：`ng_icon_kind_t` 新增 `NG_ICON_TERM`，`icon_glyph` 增加终端窗口 + `>` 提示符的极简绘制。

内核 `unlink`/`rename` 为 `vfs_unlink_path`/`vfs_rename_path` → 后端 `rename`；用户态 `apps/src/fs.rs` 新增 `unlink(path)->bool`、`rename(from,to)->bool`（调用号 20/21）。

## 8. 路线图

- **M3+**：引入进程 / 线程模型后，将 `|` 升级为真正并发管道（每个阶段独立任务，内核管道缓冲连接）。
- **cmd 别名包持久化**：OOBE 阶段把 `cmd_aliases` 写入用户配置，默认仍关闭。
- **补全与行编辑增强**：Tab 补全（文件 / 命令 / 别名）、Ctrl+U/K、增量搜索历史。
- **`rename` 跨后端**：为 ext4 适配器补齐 `rename`（或显式拷贝 + 删除回退）。
- **`$(...)` 嵌套深度放开**：随栈预算评估提高上限，或改为迭代式捕获缓冲池。
