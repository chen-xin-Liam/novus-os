# 改 Novus 的 UI：从令牌到一像素

这份文档是给"想自己改界面"的人写的。它不讲抽象的设计哲学，只讲这个仓库里
**颜色、间距、字号、控件到底在哪一行**，以及改完之后怎么确认自己没改坏。

读完你应该能做到三件事：

1. 换掉全局强调色 / 圆角 / 间距阶梯，而不必翻遍每个页面；
2. 在任意一个内置应用里加一张卡片、挪一行字，并且对得上已有栅格；
3. 用截图 + 放大图自证改动的结果，而不是"看起来差不多"。

---

## 1. 三层结构：别在下层硬写上层的东西

| 层 | 位置 | 你在这里改什么 |
| --- | --- | --- |
| 令牌（token） | `tools/themegen/theme.toml` → 生成 `apps/src/theme.rs` + `graphics/nd_theme.c` | 颜色、圆角、间距阶梯、控件高度 |
| 布局（layout） | 各应用里的常量，例如 `apps/src/bin/settings.rs` 的 `CH`、`CONTENT_X`、`CONTENT_W` | 分栏宽度、卡片位置、行的步进 |
| 绘制（paint） | `w.fill / w.frame / w.round_fill / w.text ...`（底层是 `graphics/nvgui.c`） | 一个矩形、一段文字、一根线 |

铁律：**绘制层不出现字面颜色**。看到 `w.fill(x, y, w, h, 0x0067C0)` 基本就是写错了，
应该写 `ui::accent()`。字面颜色只允许出现在令牌文件和生成文件里。

---

## 2. 令牌：改一处，全系统跟着变

`tools/themegen/theme.toml` 是唯一源：

```toml
[metrics]
radius_card  = 10     # 卡片圆角
space_xs     = 4      # 4/8/12/16/24 的阶梯起点
space_m      = 12
control_h    = 32     # 输入框、列表行、按钮的基准高度

[light]
accent       = "#0067C0"
text         = "#1B1B1B"
stroke       = "#E1E5EA"
```

改完必须重新生成，否则构建出来的还是旧值：

```sh
python3 tools/themegen/themegen.py            # 写文件
python3 tools/themegen/themegen.py --check    # 只检查生成物是否过期，CI 用
make design-tokens                            # 上面两步的构建入口
```

生成结果是提交进仓库的（构建不依赖 Python）。所以改令牌的一次提交里，
`theme.toml`、`apps/src/theme.rs`、`graphics/nd_theme.[ch]` 必须一起进。

Rust 侧读令牌只经过 `apps/src/ui.rs` 的访问器：

```rust
ui::text()   ui::dim()   ui::line()   ui::card_bg()
ui::accent() ui::good()  ui::warn()   ui::danger()
```

**为什么不让应用直接读 palette**：主题是浅色/深色两个解析结果，应用只认"语义名"。
你写 `ui::text()`，深色模式下自动变成浅字；你写 `0x001B1B1B`，深色模式下就是一块黑。

## 3. 布局：栅格是 4 的倍数

所有页面的间距只用五个值：`4 / 8 / 12 / 16 / 24`（xs/s/m/l/xl）。
这不是审美洁癖，是为了让"我把这张卡往下挪一点"永远是一个整数倍，不会累积出 3px、7px
这种没法对齐的残差——上一次"设置页标题和首张卡片只剩 4px"就是这么来的：标题块占掉了
本该属于卡片的 12px，剩下的 4px 看着就像挤在一起。

以设置页为例（`apps/src/bin/settings.rs`）：

```rust
const CH: i16 = 584;          // 内容区高度，窗口高 = CH + 标题栏
const NAV_W: i16 = 176;       // 左侧导航宽度
const CONTENT_X: i16 = 188;   // 176 + 12(间距)：内容起点
const CONTENT_W: i16 = 512;   // 剩余宽度
```

几组已经在用的数：

| 位置 | 值 | 说明 |
| --- | --- | --- |
| 卡片内边距 | 左 14、上 12 | `card()` 里写死，改这里就改全部卡片 |
| 卡片标题行高 | 约 20 | 标题之后的第一行从 `y + 40` 起 |
| 行步进 | 24 | 列表/键值行，`row_h` 的整数倍 |
| 键值列宽 | 96 | `kv()` 里 `x + 96` 放值 |
| 卡片之间 | 12 | `y + ch + 12` 才是下一张卡 |

**改一张卡的位置只有一种正确做法**：算出上一张卡的下边界，再减去 `space_m`。
不要用"看起来差不多"的绝对值去凑，因为上面任何一张卡长高 8px，你的硬编码就破了。

## 4. 绘制原语：五个函数足够画完一个页面

`apps/src/wm.rs` 暴露给应用的 `Win` 只有下面这些（每条对应一次 WM 消息，别在循环里刷屏）：

```rust
w.fill(x, y, w, h, color)                 // 实心矩形
w.frame(x, y, w, h, color)                // 1px 边框
w.round_fill(x, y, w, h, r, color)        // 圆角填充
w.round_frame(x, y, w, h, r, color)       // 圆角描边
w.text(x, y, color, str)                  // 14px 正文
w.text_big(x, y, color, str)              // 标题字号
w.shape(op, x, y, w, h, color)            // OP_HLINE/VLINE，分隔线用这个
```

四条经验：

- **边框和填充分开画**：`round_fill` + `round_frame` 是标准搭配，只画填充在深色背景上会"糊边"。
- **文字基线**：`y` 是文字块顶部，一行 14px 的字在 32px 高的控件里要写 `y + (h - 14) / 2`，
  这是 `button()` 里的写法，抄它。
- **不要为了"好看"加图层**：一个窗口的显示列表上限是 120 个图形 + 160 段文字，
  复杂页面要复用（比如卡片不单独画阴影，靠 `card_bg` 和 `line` 的对比做层级）。
- **字号只有两档**：14 正文、标题用 `text_big`。中间档没有，加了就会和别的页面不一致。

## 5. 一个完整例子：把"设备信息"卡片挪到 16px 间距

改之前（错误示范）：

```rust
w.text(CONTENT_X, 214, ui::dim(), "设备信息与实时资源");   // 硬编码 214
card(w, CONTENT_X, 242, CONTENT_W, 136, "显示输出");        // 242 - 214 - 20 = 8
```

问题：标题占 20px 行高，`242 - 214 = 28`，减去行高只剩 8px，视觉上挤。
改成阶梯值 16px，并且让卡片自己算位置：

```rust
const HEAD_Y: i16 = 214;
const HEAD_LINE: i16 = 20;                       // 标题行高
const CARD_Y: i16 = HEAD_Y + HEAD_LINE + 16;     // = 250

w.text(CONTENT_X, HEAD_Y, ui::dim(), "设备信息与实时资源");
card(w, CONTENT_X, CARD_Y, CONTENT_W, 136, "显示输出");
```

下一步所有卡片都从 `CARD_Y` 往下推 `y + 136 + 12`，不再出现魔法数。

## 6. 视觉规则清单（改之前先对一遍）

- **对齐**：左边距只有一个值（内容区 188），卡片内文字左对齐到 `x + 14`，不要在同一个页面出现两种内边距。
- **对比**：正文用 `text`，次要信息用 `dim`，两者都用令牌，不自己调灰。深色模式会自己反色。
- **层级**：靠"背景色 + 1px 描边"区分卡片，不靠阴影和粗体。阴影只有浮动层（菜单、气泡）才用。
- **命中区**：可点元素不小于 32px 高（`control_h`）；列表行整行可点，不要只让文字可点。
- **溢出**：文字宽度自己算，`NWM_TEXT_MAX` 是 96 字节，超了会被截断；中文按 3 字节/字估算，一行 512px 内最多约 22 个汉字。
- **留白**：卡片内左右各留 14，上下各留 12。宁可少放一行，也不要把间距压到 4。

## 7. 动效：只有"进入"和"状态切换"

- 窗口展开是 `NWM_REVEAL_FRAMES` 帧的 ease-out，改这个常量就改所有窗口的入场速度（`wm/novus-wm/nwm_proto.h`）。
- 目标时长 150–250ms。低于 100ms 像闪一下，高于 300ms 会挡操作。
- 不要给每个矩形加动画。动效只用在这些地方：窗口出现/关闭、焦点切换、进度条数值变化。
- 线性动画一律不用。缓出（先快后慢）才符合"东西被推出来"的直觉。

## 8. 验证：截图 + 放大，而不是"我觉得行"

```sh
make -j8 && make disk-img
# QEMU 起机，进入桌面后抓屏
```

抓屏走 QEMU monitor 的 `screendump`，然后按区域放大检查：

```python
from PIL import Image
img = Image.open('/tmp/shot.ppm')
crop = img.crop((300, 80, 1010, 560))          # 只看内容区
crop.resize((crop.width * 2, crop.height * 2), Image.NEAREST).save('/tmp/card2x.png')
```

按 2 倍放大检查三件事：**间距是否等于阶梯值、边框是否 1px 且颜色是 stroke、文字有没有压线**。
改 UI 的验收标准是"能在放大图里数出 16px"，而不是"看着舒服"。

## 9. 常见错误

| 现象 | 原因 | 修法 |
| --- | --- | --- |
| 卡片被窗口下边缘切掉 | 总高度超过 `CH`，布局没做滚动 | 减一张卡，或把内容拆到第二页 |
| 深色模式下有块黑底黑字 | 某处写了字面色值 | 换成 `ui::*()` 访问器 |
| 文字压到边框 | `y` 忘了加内边距 12 | 用 `y + 12` 起排 |
| 改了 theme.toml 但界面没变 | 没重新生成 | `make design-tokens` |
| 两个页面同样的卡片看起来不一样高 | 各自写了高度 | 把卡片高度提到常量里复用 |
| 点击没反应 | 命中区只画了文字宽 | 命中区用整行矩形，跟绘制分开算 |
