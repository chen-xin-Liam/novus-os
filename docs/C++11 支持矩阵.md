# cppcc C++11 支持矩阵

本文档是 cppcc 库化与多目标改造的**事实基线**。cppcc 的目标是完整 C++11，但语言特性按阶段落地；每个阶段只把已经实现且经过回归的特性标为“支持”，未实现的特性必须给出明确诊断，不能用部分语法接受冒充完成。

## 目标状态

| 目标 | 输出 | 入口工具 | 当前阶段 |
| --- | --- | --- | --- |
| NUC V1.0 | `*.nuc` 镜像 | `cppcc` | 已有基线，继续兼容 |
| Windows x64 | PE32+ console 可执行 | `cppcc_to_win64` | 阶段 1 完成：PE 头/节/导入表/IAT thunk/重定位，未实机验证 |
| Linux x64 | ELF64 动态可执行（glibc） | `cppcc_to_linux` | 阶段 1 完成：已在本机加载并执行 hello/C++11 smoke |

三种目标由 [`src/target/`](../user/cppcc/src/target/) 分发层统一接入：`mod.rs` 选择后端并把目标无关对象模型转换为段/符号/重定位描述；`nucgen.rs` 输出 NUC，`pe32plus.rs` 输出 PE32+，`elf64.rs` 输出 Linux ELF64。前端、语义分析和 IR 不直接引用具体容器格式，目标差异集中在该目录。

## 语言特性阶段

### 阶段 0：现有基线（已实现）

- 单翻译单元预处理、对象宏、`#include`、`#pragma once`、条件编译。
- 函数、全局变量、POD struct、enum/enum class、typedef、`static_assert`。
- 基本类型、指针、一维定长数组、引用 `T&`/`T&&`、`auto` 局部变量推导。
- 表达式、控制流、范围 for、聚合初始化、`sizeof`、`nullptr`。
- 内建 `novus_write`、`novus_yield`、`novus_exit`、`puts`、`putchar`、`exit`、`abort`。
- SysV x86_64 代码生成与 NUC V1.0 序列化；最多六个参数。

### 阶段 1：库化与多目标（已完成）

- Rust 编译 API：选项、输入集合、诊断、目标选择、产物字节。
- C ABI 静态库与稳定头文件。
- 目标无关对象模型、符号与重定位表，以及 IR 类型骨架。
- PE32+ 后端：DOS/PE 头、节表、导入表、IAT thunk、Win64 ABI 内建调用。
- ELF64 后端：ELF 头、程序头、PT_INTERP、PT_DYNAMIC、DT_NEEDED、符号表与 hash 表。
- 保留 NUC 后端与旧 CLI 参数兼容。

### 阶段 2：C++11 核心补全（进行中）

- 已实现：`-std=c++11` 显式校验、`using` 别名、`enum class`、`static_assert`、范围 for 的数组类型与游标递增修复、const 指针变量可修改性修正。
- 未实现：多翻译单元对象链接、尾置返回类型、`constexpr` 语义约束、类成员/构造析构/访问控制、继承布局与虚表、模板与变参模板实例化缓存、完整重载解析与移动语义。

### 阶段 3：运行时与标准库（规划）

- 异常、RTTI、`new`/`delete`、浮点。
- 标准库兼容头与最小运行时：`cstddef`、`type_traits`、`string`、`vector`、`map`、
  `exception` 等。
- Win64 CRT 入口与 Linux glibc 动态符号/PLT 完整支持。

## 诊断原则

1. 明确拒绝比静默接受更好：未实现特性必须在 `diagnostic::CompileError` 中说明。
2. 语法接受不等于语义支持：类型检查未覆盖的构造不能进入后端。
3. 每个目标必须支持同一份支持矩阵的子集；目标差异单列说明。
4. 回归样例至少覆盖：NUC smoke、PE32+ 结构校验、ELF64 结构校验、C ABI 往返。
