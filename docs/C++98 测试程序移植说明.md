# ISO C++98 标准库测试程序移植说明

## 目标

让 `user/win32compat/samples/C++98_head_compilation_test.cpp` **保持源码不变**，在 Novus OS 上原样编译为 PE32+ 可执行文件，并从文件管理器 `/exe` 目录启动；全部 34 个 `testCase` 输出 PASS。

## 为什么不能直接用系统 libstdc++

基线测量（MinGW `g++ -static`）显示，静态链接 libstdc++ 的同一个 `.cpp` 会：

- 导入 **122 个** Win32/CRT API（内核兼容层只实现约 20 个，其中 `msvcrt.dll` 的 85 个全部缺失）；
- 携带 **TLS 目录**（`kernel/pe.c` 原先对任何 TLS 镜像直接拒绝）；
- 携带 **SEH 异常表**（依赖 `__gxx_personality_seh0` / `Rtl*Unwind`）。

因此改用「自研标准库 + G++ 仅作前端」的路线：编译期排除 libstdc++/libgcc/CRT，运行时只依赖内核已有的少量 kernel32 API。

## 方案

### 1. 关键字接管（异常 / RTTI）

`user/win32compat/include/__novus_except.h` 用宏接管 C++ 关键字：

- `try` → `if (__builtin_setjmp(jb) == 0 && enter())`
- `catch(x)` → `else if (caught())`
- `throw` → `g_throw =`（`novus_thrower::operator=` 永不返回，直接 `__builtin_longjmp`）
- `typeid(x)` → `novus_typeid_impl(#x)`

`__builtin_setjmp/longjmp` 与 `__builtin_va_*` 经基线验证在 `-fno-exceptions -fno-rtti -nostdlib` 下完全自包含，不引入 libgcc。

编译关键 flag：`-std=c++98 -nostdinc++ -I user/win32compat/include -fno-exceptions -fno-rtti -fno-threadsafe-statics -fno-builtin -fno-stack-protector -fno-asynchronous-unwind-tables`。

`-fno-builtin` 是必需的：否则 `-O` 优化会把自研的 `novus_strlen` 换成 CRT `strlen` 调用。

### 2. 自研标准库头

`user/win32compat/include/` 提供测试 `#include` 的全部头文件：

- CRT：`cstddef cstdio cstdlib cstring ctime cmath cctype climits cfloat cstdarg csetjmp csignal`
- 流/字符串：`iostream sstream fstream string`
- 容器/算法：`vector list deque map set queue stack algorithm functional iterator numeric utility memory limits stdexcept typeinfo locale bitset`
- `windows.h`：`HANDLE/DWORD/GetStdHandle/WriteFile/SetConsoleTextAttribute` 与 `FOREGROUND_*` 常量

实现均为 header-only，`iostream`/`fstream` 输出到 `WriteFile`，文件读写用一个进程内的暂存表（测试只在同一进程内写后读 `_cpp98_test.tmp`）。数学 `sqrt` 用一条 `sqrtsd` 内联汇编。

### 3. 内核侧

- `kernel/win32.c/.h`：新增 `WIN32_API_SET_CONSOLE_TEXT_ATTR`，`g_api[]` 增加 `SetConsoleTextAttribute` 映射，dispatch 增加 case；实现把 `FOREGROUND_*` 属性映射为 ANSI SGR 序列写到串口（复用 `kputs`）。`WIN32_API_COUNT` 从 133 提升到 134。
- `kernel/apps.c`：`g_win32[]` 末尾增加 `cpp98test.exe` 条目（不挪动既有 NUC/WIN32 索引）。
- `Makefile`：新增 `CXX`；新增 `out/win32/cpp98test.exe` 显式规则；加入 `WIN32_BINS` 与 `build/win32_blobs.h` 的 `xxd -i` 生成。
- `kernel/pe.c`：扩展了 PE 加载器能力（通用增强，不只为本测试）：
  - 新增对 `IMAGE_TLS_DIRECTORY64` 的支持。原先对任何带 TLS 目录的镜像直接判 `PE_EFORMAT`；现在解析 40 字节目录，把 raw TLS 模板拷到 `WIN32_TLS_DATA_VA (0x60002000)`，点到 TEB slot 0（`%fs:0x1480`），并把保留索引 0 写入模块的 `_tls_index`。TLS 目录的 4 个 VA 字段由链接器放入 `.reloc` 表，`pe_relocate()` 加过 delta 后即为加载后有效地址（已用真实 `libwinpthread-1.dll` 核对字段布局与重定位覆盖）。回调数组接受但不执行。
  - 提升硬上限：`PE_MAX_IMPORTS` 64 → 256、`PE_MAX_RELOCS` 4096 → 65536，以容纳静态链接 C++ 运行时更大的导入/重定位表；仍保持有界以防畸形镜像。
  - 新增 `PE_ETLS` 错误码；TLS 初始化在 task 创建后、TEB 映射后进行，失败时 `sched_kill` 回收，不留半启动任务。
  - 向后兼容：无 TLS 目录的镜像走原来的 no-op 路径。本文档的 `cpp98test.exe` 无 TLS（导入 7、重定位 6），验证时加载器行为与改动前一致；QEMU 下 `[PE] selftest PASS` 与 34/34 全 PASS 均确认无回归。

最终 exe：约 22 KiB，6 个 section，7 个导入（`GetStdHandle/WriteFile/GetProcessHeap/HeapAlloc/HeapFree/GetTickCount64/SetConsoleTextAttribute`），全部在内核兼容层内。

### 4. Rust 工具

计划中的 `tools/cpp98_depcheck.rs` 未新增：本方案把依赖面压缩到 7 个 API，已用主机脚本 `out/baseline/{pe_probe,check_api}.py` 直接核对 PE 导入表与 `g_api` 表/枚举一致性；这些是探索期临时脚本，不是产品依赖。如需长期 CI 校验，可再补 Rust 版工具。

## 构建与运行

```bash
export PATH=/home/dev/.rustup/toolchains/stable-x86_64-unknown-linux-gnu/bin:$PATH
make -j4                 # 构建内核 + 全部 Win32 样例（含 cpp98test.exe）
make iso                 # 生成 out/novus-live.iso
```

启动后：

- 文件管理器进入 `/exe` 虚拟目录，可见 `cpp98test.exe`，点击运行；
- 或在 `nsh` 中直接输入 `cpp98test.exe`（`spawn_name` 按名解析）。

预期串口/终端输出以 `===== ISO C++98 Standard Library Full Functional Test =====` 开头，以 `>>> ALL TESTS PASSED <<<` 结尾，34 项全 PASS，进程退出码 0。

## 已知限制

- 异常为宏模拟的单一活动上下文（setjmp/longjmp），不是完整的 Itanium ABI；足够覆盖该测试的单个 `try/catch` 与 `typeid(double)`，不支持嵌套异常传播/`catch` 类型匹配。
- `fstream` 使用进程内暂存表而非真实 VFS 文件；测试语义（写后读）成立，但跨进程/掉电不持久。
- `signal`/`atexit` 为注册占位实现；测试只验证可注册性。
- 颜色输出为 ANSI SGR 文本序列；普通串口日志查看器会看到转义码，ANSI 终端会显示颜色。
