## 一、可复现的核查环境

Linux（Ubuntu 22.04 用户态，非 root）上从源码到镜像全流程跑通：

| 环节 | 结果 |
|---|---|
| 交叉工具链 `x86_64-w64-mingw32-gcc` (GCC 10-posix) | 手工解包 deb 到 `$HOME/local` |
| Rust `cargo 1.100.0` + `x86_64-pc-windows-msvc` / `x86_64-unknown-none` | rustup 安装 |
| `make -j2` → `out/NOVUS.EFI` | **exit 0，通过** |
| `make disk-img` → `out/novus-disk.img`（64MiB，ESP + NovusFS 系统分区） | **exit 0，通过** |
| QEMU 6.2 + OVMF(`OVMF_CODE_4M.fd`) `-machine q35 -smp 2 -m 2560` | 启动到桌面 |
| 连续 3 次冷启动复现 | 缺陷 **3/3 稳定复现** |

启动参数要点（`-m` 低于 2GiB 会被内核拒绝；`HALT` 后 A 核 park、B 核进调度器）。

### 构建侧的两个坑（不是业务代码 bug，但会让别人构建不出来）

1. 缺 `x86_64-unknown-none` 的 rust-std 时，`apps` 直接报 `error[E0463]: can't find crate for 'core'`（`Makefile:333 build/apps.stamp Error 101`）。
2. apps 嵌入依赖系统 `xxd` 支持 `-n`。本机 `xxd`（精简版）不支持 `-n` 时会打印 usage，`build/apps_blobs.h` 生成成空壳，随后 `kernel/apps.c` 报一串 `k_app_fileman / k_app_taskman ... undeclared`（`Makefile:408 build/kernel_apps.o Error 1`）。补一个 `xxd -i -n` 包装脚本后编译通过。`build/win32_blobs.h` 同理（`k_app_hello_exe` 未定义）。

## 二、实测缺陷清单（3 次冷启动一致）

### 1. 壁纸包完全没生效（功能性缺陷）
启动阶段明明读到了包：

```
[FAT] read 3685166 bytes
[WPKG] wallpaper package staged: 3685166 bytes for the kernel stage
[BOOT] live root: 8192 KiB at 0x000000009C309000
```

内核侧却认为是空的：

```
[WP] no wallpaper package staged: flat desktop colour
[M3] no live root published by the boot stage
```

结果：桌面只剩纯色渐变，仓库里 7 张 1920 宽的真实照片壁纸（`assets/backgrounds/`）全部白加。
→ boot stage 与 kernel 之间 live root / 壁纸包的参数传递不一致，这是"素材加了、功能没生效"的典型。

### 2. 显示子系统自检失败（文字度量是坏的）
```
[ND] FAIL: text width
[ND] FAIL: text width 2x
[ND] selftest: 0x23 checks passed, 0x2 failed
[ND] selftest FAIL
```
23 项过、2 项失败，失败的正是**文字宽度度量**。这与 `docs/pic/` 里 10-24 截图暴露的"标题与正文重叠"（设置页"关于"、网络页三处卡片标题）是同一个根因，且 `48e70fc 修复一些bug` 对 `graphics/nd_font.c` 的改动只是把调试打印换成另一处物理地址读，并没有修度量。

### 3. 全屏白/黑横带 + 磁贴残影（脏矩形重绘坏了）
1024×768 下固定出现：

| 区域 | 现象 |
|---|---|
| y = 161–176（全宽 16px） | 纯白横带 |
| y ≈ 177–208 | 纯黑横带 |
| y = 209–239 | 纯白横带 |

同一位置在 3 次启动、以及鼠标按键/移动后重复出现；左上角还会出现"文件管理器"磁贴的错位残影。`nd_demo.c` 里 `nd_demo_tick()` 的 damage 合并 + `nd_present(d)` 局部呈现路径显然没把旧内容擦干净。

### 4. 桌面中央多出一块空白窗口
固定位置深灰块：**x 303–722（宽 420px）、y 242–约 492（高约 250px）**，无标题、无内容、无边框细节。
`graphics/nd_demo.c:219` 的 `nd_selftest()` 会 `ng_create(... NG_WINDOW, 10, 10, 220, 190)` 建一个 "probe" 窗口跑控件自检，全文件**没有任何 destroy 调用**，自检窗口留在了桌面上。

### 5. 部分图标渲染成白方块
桌面磁贴与任务栏里的"终端""设备管理器"等图标显示为纯白色方块；任务栏中段还有两个同样的白块。图标字形缺失或未绘制。

### 6. 无系统分区的 live 启动：内核直接崩
不挂系统分区的 live 启动路径，启动 fileman / taskman / settings 三个应用后：
```
[APPS] launching settings (0xFA94 bytes)
[NUC] settings: 1 segments, entry 0x400000
[TRAP] #GP general protection err=0 rip=0x9D9FD37E cs=0x8
[TRAP] kernel fault: halting
```
同一路径下所有中文变成豆腐块（"文件管理器"等全是方格），因为字体改为运行时从 live root 加载（`nd_font_load_from(fs)`），没有 live root 就没有中文。挂上磁盘镜像后中文恢复，说明字体路径依赖系统分区，降级体验为零。

## 三、UI 做到了什么程度

**设计体系确实建完了**（静态面证据扎实）：

- `graphics/nd_theme.c`：浅/深两套语义色 token + 一套 `nd_metrics_t`（radius_control 6 / radius_card 10 / pill 18、control_h 32、button_h 36、row_h 28）
- 风格：Win11 Fluent / Mica 渐变 / 圆角 / 语义色 / 思源黑体（heading 28、subheading 16、body 14）
- 组件：`graphics/nvgui.c` 54.6KB、`nvgui.h` 10.4KB；`wm/novus-wm/wm.c` 48.4KB 双缓冲合成
- 桌面壳层：`graphics/nd_demo.c` 36.5KB，居中悬浮任务栏、圆角磁贴、时钟/音量
- 素材：7 张真实照片壁纸（含 `backgrounds-screen`）、3.49MB 字模 + 353KB unicode 表
- 应用规模：settings.rs 660 行、setup.rs 821 行（图形安装向导）、fileman.rs 730 行、netman 240、taskman 329、nsh 514
- 计划文档 `.codebuddy/plans/novus-ui-and-graphical-installer_*.md` 的 8 条 todo 全部 completed；全仓 TODO/FIXME/XXX/HACK 仅 2 处命中且都是误报

实机画面也确实已经是 Win11 那一套（深色 Mica、居中任务栏、磁贴、圆角、中文字体正常）。**所以"改 UI"的方向和骨架是完成了的。**

问题在落地：壁纸不生效、文字度量自检失败、图标缺失、空白窗口泄漏、整屏绘制横带。按实机表现，这一版**不能算"改好看了"**，是"骨架像 Win11，画面不干净"。

## 四、未验证项（如实说明，不要当成结论）

1. **设置 / 网络 / 文件管理器窗口内部排版**（10-24 旧截图里的"关于"标题与副标题重叠、"链路/类型""地址/IP""计数与测试"标题压正文、文件管理器底部按钮被裁切）——本环境 headless 下只有 PS/2 相对指针（带加速），坐标无法精确落到磁贴上，三次点选都没打开应用窗口，**未能复验**。但第 2 项自检失败指向同一根因，建议在开发机上点开这三个应用重新截图确认。
2. **桌面点击 / 开始菜单 / 键盘输入**：headless 下 `sendkey` 与按钮注入不可靠（boot 菜单按 3 都没被接收），只证到"指针移动→hover 高亮"这条链是通的。**交互是否正常需要在有窗口的环境复核。**
3. **图形安装向导界面**（`setup.rs`）——需要从启动菜单选 3 进入，本环境没能注入按键，未截到。

## 五、给 Liam 的修复优先级（按影响面）

1. **boot stage → kernel 的参数传递**（壁纸包 + live root 同一处）：一修两个问题（照片壁纸生效、`[M3] no live root` 消失）。
2. **`nd_font` / 文字宽度度量**：`[ND] FAIL: text width` 自检已经是红的，这也是所有重叠/裁切的根因。
3. **脏矩形重绘**：白/黑整屏横带、磁贴残影、指针旧位置没擦掉，都在 `nd_demo_tick` + `nd_present` 这条路径上。
4. **自检窗口泄漏**：`nd_selftest()` 建的 probe 窗口用完要销毁，否则每次启动桌面中央都留一块空窗口。
5. **图标字形补齐**：终端、设备管理器、任务栏中段两个白块。
6. **无 live root 的降级**：没有系统分区时至少回退内置字模与纯色桌面，别直接 `#GP halting`。
