# M8 内置系统应用（Rust 用户态）

M7 的 C++ 编译器跳过，M8 的三个系统应用直接用 **Rust** 编写：文件管理器、
任务管理器、设置面板。它们不是内核里的函数，而是真正的 ring-3 进程 ——
用 `syscall` 取 pid、查端口、发 IPC、等事件，窗口内容通过 Novus-WM 的
显示列表提交。整个用户态运行时就是 `apps/src/` 里的五个模块，无标准库、
无分配器、无第三方依赖。

---

## 1. 目录

```
apps/
  Cargo.toml            三个 bin + 共享库，x86_64-unknown-none
  .cargo/config.toml    目标与链接参数
  link.ld               .text 起于 0x400000，_start 在最前
  src/lib.rs            运行时入口（panic handler）
  src/sys.rs            系统调用封装（call/getpid/write/yield/ipc/exit）
  src/ipc.rs            IPC 报文格式、收发、按名字找端口
  src/wm.rs             Novus-WM 客户端：建窗、移动、显示列表、事件
  src/sinfo.rs          sysinfo 服务客户端：任务表、文件树、统计、主题色
  src/ui.rs             调色板、整数格式化、定宽文本、行/按钮
  src/bin/fileman.rs    文件管理器
  src/bin/taskman.rs    任务管理器
  src/bin/settings.rs   设置面板
```

## 2. 从源码到桌面

```
cargo build --release --target x86_64-unknown-none
        │  ELF，_start 在 0x400000
        ▼
objcopy -O binary          → out/apps/<app>.bin（扁平镜像，无 ELF 头）
        ▼
xxd -i -n k_app_<app>      → build/apps_blobs.h（C 数组）
        ▼
kernel/apps.c              → 应用表{名字, 指针, 大小}
        ▼
nuc_spawn_blob(name, blob, size, 0)  → 映射到 0x400000、64 KiB 用户栈、ring 3
```

链接脚本把 `.bss` 放在 `.rodata`/`.data` 之前，原因是 `objcopy -O binary`
不写 NOBITS 段：只有在零初始化段之后还有内容时，扁平镜像才会覆盖它的
地址范围，`nuc_spawn_blob` 的映射才不会短一截。

启动时 `kmain` 依次拉起三个应用；桌面顶部的任务栏（`graphics/nd_demo.c`）
再点同名按钮时 `apps_launch()` 用任务名判重，返回 `APPS_ERUNNING`，
文件管理器据此显示 “already running”。

## 3. sysinfo 服务（`kernel/sysinfo.c`）

端口名 `"sys"`，与 WM 同一个 tick 里泵消息，每次最多 8 条。列表分页，
一条应答最多 3 条记录，保证载荷不超 128 字节。

| 请求 | 载荷 | 应答 | 载荷 |
|------|------|------|------|
| 0x0301 TASKS | `{index, max, dir=0xFF}` | 0x0311 | `{total, n, rec[3]}` |
| 0x0302 FILES | `{index, max, dir}` | 0x0312 | `{total, n, rec[3]}` |
| 0x0303 STATS | — | 0x0313 | `{uptime, free_kb, tasks, windows, ipc_sent, ipc_drop, accent}` |
| 0x0304 ACCENT | `{rgb, set}` | 0x0314 | `u32` 当前主题色 |
| 0x0305 SPAWN | `{which}` | 0x0310 | `i32`（0 成功，-100 已在运行） |

`sys_task_rec_t` 32 字节：pid、ticks、exit_code、state、slice、name[14]。
`sys_file_rec_t` 32 字节：size、kind、name[24]。目录：`/apps`（内嵌应用，
可运行）、`/dev`（fb0/ps2/serial）、`/proc`（tasks/ipc/mem）。

主题色不是应用自己的状态：ACCENT 请求写的是 `ng_ctx.theme.accent`，WM 的
焦点框、标题栏高亮和 shell 的进度条都从这一处取色，所以设置面板一改，
整个桌面一起重绘。

## 4. 显示列表（WM 协议 1.1）

窗口内容不再是 7 条定长命令，而是每窗一份列表，客户端用三条消息维护：

| 请求 | 作用 |
|------|------|
| 0x010D CLEAR | 清空形状与文本列表（一帧的开始） |
| 0x010E SHAPE | 追加一个图元 `{op,x,y,w,h,color}`（填充/边框/横线/竖线/圆） |
| 0x010F TEXT | 追加一段文字 `{x,y,scale,len,color,text[96]}` |

上限 `NWM_MAX_SHAPES` 28 / `NWM_MAX_TEXTS` 40，足够一屏列表。字体是定点
5x7、步进 6px，所以对齐靠**空格补齐**（`ui::Buf::col(n)`），一行一条文本，
既省消息数也省列表槽位。

`ipc_send` 遇到队列满会返回 `EBUSY`：`wm::send` 在重试，直到 WM 把队列
腾出来，否则一次重绘（20 多条消息）会在中途断掉，留下半帧。

## 5. 应用

**文件管理器**（416x304）：三个目录标签、条目列表（名称 + 大小/类型）、
Run 按钮。`/apps` 下的条目按内核应用表顺序排列，Run 用的就是这个下标。

**任务管理器**（426x286）：每行 `名称 | 状态 | pid | 累计 tick`，`run`
状态高亮；底部是任务槽占用条和 Refresh。每 40 次 `yield` 自动刷新一次。

**设置面板**（356x250）：四个主题色块，点一下改全局强调色；下面是
uptime、空闲内存、任务数、窗口数、IPC 收发计数。这些数字全部来自
sysinfo，所以它同时也是最快的“系统是否活着”的观察窗。

## 6. 验证

1. 启动日志：`[APPS] launching fileman (5552 bytes)` × 3，随后
   `[APP] fileman up` 等三行；
2. 任务管理器列出 5 个任务（idle/spin/三个应用），状态与 pid 与
   `[SCHED]` 日志一致；
3. 文件管理器 `/apps` 显示三个应用及大小，Run 已运行的显示
   “already running”；
4. 设置面板点色块，shell 进度条与所有窗口焦点框同时换色；
5. 关闭任一窗口 → WM `destroy`，任务退出；再点任务栏按钮可重新拉起；
6. 标题栏拖动、点击客户区事件、关闭按钮与 M6 一致。
